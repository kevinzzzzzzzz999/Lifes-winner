# 发布前隐私检查

在仓库根目录执行：

```sh
python3 scripts/check-publication.py
```

检查只读取准备好的公开源码树，默认根目录是脚本所属仓库。不会访问用户笔记目录、浏览器账号或系统凭据。`--root` 可用于另一个明确准备好的源码副本。

维护者可以在仓库外准备一个 JSON 字符串数组，列出不能公开的姓名、账号、完整邮箱、设备标识等，再执行：

```sh
python3 scripts/check-publication.py --denylist ../publication-denylist.json
```

这个私人清单必须位于仓库外。检查器不输出清单或文件正文；失败结果只包含相对路径和规则名。相对路径本身包含清单词或高置信凭据时，对应片段也会遮盖。清单按 Unicode 规范化并忽略大小写匹配。第三方公开许可证中的邮箱不会被笼统禁止；只有与私人清单相符时才需要检查来源。

## 检查范围

- 拒绝源树中的符号链接、非普通文件、凭据文件、签名文件、数据库、诊断日志和安装包。
- 检测常见高置信 API 密钥、访问令牌、私钥头，以及硬编码的个人主目录路径。
- PNG 逐块核验结构和校验值，拒绝 EXIF、文本、国际化文本、压缩文本及内容凭证元数据；ICO、ICNS 内嵌 PNG 同样检查。
- 二进制只接受格式签名正确的 PNG、ICO、ICNS、WOFF、WOFF2、TTF、OTF、TTC。其他源文件必须是已列明类型的文本。单文件超过 64 MiB 会停止放行。
- 另有按完整相对路径和 SHA-256 固定的少量已审核例外：斜线图像及合成正弦音测试、三份合成 Office/PDF 文档，以及仓库中三份既有公开源码 ZIP。斜线图像自带固定的生成元数据，已人工核对。WAV、PDF、Office 和 ZIP 没有通用后缀放行；例外文件字节变化会失败，新增同类文件也会失败。ZIP/Office 成员仅在内存读取，继续检查密钥、私人路径和外部私人清单，不解压到磁盘、不执行内容。
- 所有受检内容仍检查私人清单，包括允许的图片和字体容器中的可读字符串。

当前 `source-manifest.json` 也可指定唯一待发布源码 ZIP：`archive` 必须是仓库根目录的 ZIP 文件名，`archivePrefix` 必须是 `Lifes-winner/`，并提供整个归档的 `archiveSha256`。`sourceFiles` 的每一项都必须列出仓库相对 `path`、`bytes` 和 `sha256`。检查器严格核对归档摘要、精确成员集合、成员大小和摘要，拒绝重复、未知、缺失、不安全路径和符号链接。即使所有摘要相符，内部源码仍执行格式、密钥、私人主目录与外部私人清单检查；生成目录不能因列入清单而获准。归档仅在内存读取，不展开或执行。此方式避免把新归档的摘要写入它自身包含的检查器，也不会放行其他 ZIP。

Git 元数据、依赖目录和生成目录不属于发布源树检查范围，包括 `node_modules`、`dist`、`DerivedData`、`.build` 及已列明工具缓存。桌面生成目录按精确路径排除：`desktop/release`、`desktop/runtime`、`desktop/.release-work`、`desktop/.development`、`desktop/.cache`、`desktop/.release`。`desktop/scripts/release/` 是维护源码，完整受检；不会因目录名为 release 而跳过。普通 `build` 目录跳过；`desktop/build` 中明确用于应用的三个 `icon` 文件会检查。`desktop/public/pdfjs` 由锁定依赖在构建时生成，也跳过。安全导出和提交时仍必须排除生成目录，不能只依赖检查器。

两份未修改的 vendored SheetJS 文件包含合法的代码页字符表，其中使用了非 NUL 控制字符。检查器仅接受这两个明确相对路径及其固定上游 SHA-256 的原始字节；更新版本需重新审阅。该例外不会跳过凭据、私人路径或私人清单检查，也不适用于整个第三方目录。

两份精确 SHA 固定的浏览器拒绝测试源码含有虚构的个人主目录 URL。仅这些已审字节免于私人主目录误报；修改后恢复普通路径检查。密钥模式与私人清单检查始终执行，也没有针对整个 tests 目录的放行规则。

## 结果与边界

退出码 `0` 表示受检源文件通过，`1` 表示发现待处理内容，`2` 表示参数或私人清单不符合要求。输出不包含发现的密钥、个人词或文件正文。

机械检查不能判断所有文字或图像像素是否包含私人资料。发布流程应先按明确的源码清单导出，再执行检查并审阅新增文件。私人笔记、课程原件、截图、个人账号配置和设备记录不应进入公开副本；实际业务测试和构建日志也不要直接提交。

检查器已经在隔离目录验证：合成密钥、合成个人主目录路径、符号链接、签名文件、未知二进制、PNG 文本元数据、图标内嵌 PNG 元数据、私人清单命中都会失败；干净源码及无元数据 PNG 可以通过；仓库内的私人清单会被拒绝。

GitHub Actions 中的 `Verify reviewed source privacy` 仅支持手动启动，只有读取仓库权限，只运行本检查器。旧的历史源码归档展开、自动提交和回写 main 已停用；这不是自动构建或发布安装包的流程。
